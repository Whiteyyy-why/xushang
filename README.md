# 续上

本地工作现场记录工具，支持 Git 仓库和普通文件夹。明亮界面与原创 SVG 图标，不需要 GitHub、账号或模型 API Key。

## 启动

需要 Node.js 22+。Git 项目额外需要 Git。

**Windows：双击 start.cmd**，或运行：

~~~sh
npm start
~~~

默认地址：http://127.0.0.1:4318/ 。重复启动会打开已有服务。关闭服务后，已保存笔记仍在。没有运行时第三方依赖，不需要 npm install。

## 使用

| 需求 | 入口 |
|---|---|
| 接入 Git 或普通文件夹 | 接入与存储 → 接入项目 |
| 开始工作并自动存草稿 | 工作台 → 开始这一段 |
| 收工留下下一步 | 工作台 → 收工，留下一步 |
| 临时离开再恢复 | 未收工草稿 → 接着写 |
| 控制大仓库检查成本 | 工作台 → 检查范围 |
| 停止后台检查 | 工作台 → 停止检查 |
| 回看决定 | 工作记忆 → 按需加载更早现场 |
| 跳回文件 | 继续这个现场（VS Code），或复制位置 |
| 备份/迁移 | JSON 导出与导入 |
| 阅读工作笔记 | Markdown 导出 |

第一次可创建“小岛”示例。它是独立的真实本地文件夹。

## 日常使用

开始工作时，直接接上上次的下一步；随手记自动存草稿。刷新或重新打开后可恢复。收工时只补一句“下次先做什么”，其他信息可展开调整。

快捷键：Ctrl / ⌘ + Alt + Enter 进入专注；Ctrl / ⌘ + Alt + S 收工；收工表单内 Ctrl / ⌘ + Enter 保存。

JSON / Markdown 导出包含未归档草稿。多窗口有冲突时会保留本页输入，让你选择要继续使用的版本。

[日常工作流程与草稿边界](docs/DAILY-WORK.md)

## 大仓库

**笔记先落盘，检查后补齐。** 打开和保存都不等待 Git。

默认检查 Git 改动与关注文件，不枚举未跟踪目录。建议把关注范围设为当前模块；也可显式选择全量范围或纳入未跟踪项。5 秒时间预算、输出和文件数量上限始终生效，超限显示“部分完成”。

本机合成测试：10 万受跟踪文件 + 2 万未跟踪文件。限定一个关注文件时，保存接口中位数 **7ms**，打开接口中位数 **31ms**。默认范围的冷检查触发预算，未被伪装成完整扫描。

[大仓库方案、边界与测试方法](docs/LARGE-REPOS.md)

## 数据

数据默认保存在 .xushang-data/，已被 Git 忽略。可用 XUSHANG_DATA_DIR 改位置，用 PORT 改端口。

新版保留旧版数据，使用检查点与增量日志；不随每次保存重写所有历史。记录包含文字、文件路径、内容指纹和 Git 元信息，**不包含源文件正文，不提供源码回滚**。文件摘要按后台实际采集时间记录。

Git 项目尊重忽略规则，并跳过符号链接、依赖/构建目录、常见密钥文件。普通目录支持 .xushangignore：每行一个相对路径、目录或 * 通配符，# 为注释，不支持 ! 反向匹配。

每次最多比较 5,000 个文件，单文件 2MB，读取 64MB。未完成的范围明确标注。大仓库的全量检查与极长历史的冷启动仍可能较慢。

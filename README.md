# 续上

一个本地运行的工作现场记录工具。Git 仓库和普通文件夹都可以使用，无需 GitHub、账号或模型 API Key。

## 启动

需要 Node.js 22+。Git 项目额外需要 Git；普通文件夹不需要。

**Windows：双击 `start.cmd`。** 也可以运行：

~~~sh
npm start
~~~

打开地址：**http://127.0.0.1:4318/**

重复启动会打开已有应用。关闭服务窗口后应用停止；现场记录保留。无需 `npm install`，没有运行时第三方依赖。

## 使用

| 你想做什么 | 入口 |
|---|---|
| 接入本地 Git 或普通文件夹 | 接入与存储 → 接入项目 |
| 保存当前思路与下一步 | 工作台 → 留个现场 |
| 找回之前的决定 | 工作记忆 |
| 查看离开后的新增、修改、删除 | 工作台 → 离开之后 |
| 跳回 VS Code | 继续这个现场；可指定相对文件路径和行号 |
| 没有安装 VS Code | 复制位置，手动打开 |
| 备份/迁移记录 | 接入与存储 → JSON 备份 / 导入 |
| 阅读或分享自己的工作笔记 | Markdown 导出 |

第一次打开可以显式创建“小岛”示例。示例是独立的真实本地文件夹，可以修改并体验变化比较。

## 速度

~~~mermaid
flowchart LR
  A[打开页面] --> B[立即读取已保存的现场]
  B --> C[看笔记 / 找下一步]
  B --> D[后台检查文件和 Git]
  D --> E[更新变化卡片]
~~~

- 打开现场不等待 Git；扫描失败也能阅读原来的记录。
- 60 秒内复用检查结果，切换项目不重复扫描。
- 自动检查按大小和修改时间复用指纹。手动刷新和保存现场会重新读取内容。
- 只传输当前项目的现场摘要，不在首屏发送整段历史的文件指纹。

本机合成基准：1,000 个文件、100 条现场。列表和详情接口合计中位数 **30ms**，P95 **32ms**；服务重启 **134ms**；首次保存含扫描 **3.4s**。这是当前机器的测试数据，不代表所有设备。可运行 `node scripts/benchmark.js` 重测。

## 本地数据

默认在项目目录的 `.xushang-data/`；已加入 Git 忽略。可用 `XUSHANG_DATA_DIR` 指定其他路径，用 `PORT` 指定端口。

记录包含笔记、路径、内容指纹和 Git 元信息，**不包含源文件正文，不提供源码回滚**。JSON 导入追加并去重，不覆盖已有现场。

服务仅监听 `127.0.0.1`。数据文件原子替换，保留上一份有效备份；一个数据目录只允许一个运行实例。

## 扫描范围

- Git 项目使用本地 Git 文件清单，尊重 Git 忽略规则。与 GitHub/GitLab/Gitee 等托管平台无关。
- 跳过符号链接、常见依赖/构建目录、`.env*`、私钥和证书文件。
- 默认最多 5,000 个文件、单文件 2MB、单次读取 64MB。达到限制会标记“扫描不完整”，不会直接把未扫描文件判定为删除。
- 在项目根目录创建 `.xushangignore` 可补充忽略规则：一行一个相对路径、目录或 `*` 通配符；`#` 开头为注释。暂不支持 Git ignore 的 `!` 反向匹配语义。
- 网络盘、极大目录的后台检查可能较慢；仍可先使用已保存的现场。

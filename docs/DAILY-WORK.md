# 0.3 · 减少日常记录的负担

## 新流程

~~~mermaid
flowchart LR
  A[打开项目] --> B{有未收工草稿?}
  B -->|有| C[恢复目标、随手记和位置]
  B -->|没有| D[从上次的下一步开始]
  C --> E[专注工作 / 输入自动存草稿]
  D --> E
  E --> F[收工：只补一句下一步]
  F --> G[归档现场并清理对应草稿]
  G --> A
~~~

| 场景 | 操作 |
|---|---|
| 开始工作 | “开始这一段”，沿用上次的下一步作为当前目标 |
| 中途有想法 | 写进“随手记”，无需单独点击保存 |
| 临时离开 | 返回工作台；草稿继续保留 |
| 再回来 | 恢复未收工草稿，目标、笔记、文件位置都保留 |
| 收工 | 主表单只显示“下一步”；标题与其他信息可展开调整 |
| 直接记录 | 不进入专注模式，也可以直接留下下一步 |

## 快捷键（仅在续上页面内）

| 快捷键 | 作用 |
|---|---|
| Ctrl / ⌘ + Alt + Enter | 进入专注工作 |
| Ctrl / ⌘ + Alt + S | 打开收工表单 |
| Ctrl / ⌘ + Enter | 提交收工表单 |

Mac 的 Alt 对应 Option。输入法组合期间不会触发这些动作。

## 草稿的可靠性

- 每次输入立即保留浏览器暂存副本；停止输入约 650ms 后保存到本机。
- 只有本机服务确认成功，才显示“草稿已保存到本机”。
- 已确认的草稿存入独立文件，不触发 Git，也不为每次按键追加历史快照。
- 后台刷新只更新旁边的检查结果，不替换正在输入的编辑区域。
- 多窗口使用版本校验。冲突时保留本页输入，并展示已保存版本供用户选择。
- 收工只清理本次对应版本的草稿；重复提交不会增加重复现场或清空新草稿。
- 导出前先同步当前页面的待保存草稿；JSON 和 Markdown 都包含未归档草稿。
- 导入时保留本机已有草稿，不自动覆盖正在进行的工作。
- 草稿文件名使用项目标识的摘要，不直接拼接外部路径。

## 实现边界

| 模块 | 职责 |
|---|---|
| src/drafts.js | 草稿独立落盘、版本冲突、收工后的清理 |
| public/work.js | 浏览器暂存、自动保存、恢复、专注编辑区域 |
| src/service.js | 草稿与正式现场的衔接、备份与恢复 |
| src/store.js | 正式现场的增量日志和重复保存识别 |

草稿保存在 .xushang-data/drafts/，旧现场格式继续兼容。未获本机确认的最后几次输入依赖当前浏览器暂存；使用另一浏览器或更改端口时，这份暂存不共享。

本版本只自动保存你在续上输入的内容。尚未自动读取编辑器正在打开的文件、光标或思考过程，也没有后台记录其他应用。

## 验证与实际价值

自动化覆盖草稿恢复、输入途中保存、多窗口版本冲突、项目切换、重复收工、备份与收工并发，以及原有大仓库行为。

真实页面已验证输入与光标保留、刷新恢复、收工快捷键、收工后清理、项目隔离和页面适配。检查记录见 VALIDATION.md。

“10 秒内收工、30 秒内继续工作”仍是实际使用的目标，不是已经测得的人类操作时间。产品是否能让人主动使用，需要通过真实项目的一周体验来验证。
